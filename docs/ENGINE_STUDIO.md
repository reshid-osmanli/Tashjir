# استوديو المحرك — Engine Studio

> بيئة رسومية لتعليم المحرك: الأولويات، القواعد، متى يُدمج ومتى لا، سياسات
> القرار، واختبارها — دون العودة إلى الكود أو تحرير JSON يدويًا.

استوديو المحرك (`/studio`) هو طبقة **القرار والسياسة** في البنية المستهدفة.
المحرك الكودي (خوارزميات القياس والتخطيط وضرب الأوجه وتوليد الأسطر) يبقى
كودًا في `lib/tashjeer/*`، بينما تنتقل كل القرارات القابلة للتهيئة (الأولوية،
الدمج، منع الدمج، السياق، الاستثناءات، حل التعارض، ترتيب التنفيذ) إلى نموذج
إعداد موحّد يُدار من هنا.

```
Engine Studio (طبقة القرار والسياسة — يعلّمها المستخدم)
        ▼
Decision Resolver (حلّ القرار المركزي — مكوّن واحد)
        ▼
Engine Core (خوارزميات التنفيذ — كود)
```

---

## المبدأ المعماري

- **Engine Code = Execution Engine**: الخوارزميات الأساسية تبقى كودًا (P-08).
- **Engine Studio = Decision & Configuration Layer**: كل قرار قابل للتهيئة
  ينتقل إلى نموذج Configuration موحّد.
- **قرار واحد في مكان واحد**: كل أسئلة «أيهما يفوز؟ هل يُدمج؟ ما ترتيبه؟»
  يجيب عنها Decision Resolver وحده (P-07). لا تملك أي ميزة تنفيذًا خاصًا.
- **المحرك يقترح والمحرر يقرر**: عند التصحيح تُحفظ `Engine = A` و`Editor = B`
  و`Final = B`؛ لا تُحذف A (P-06).

## الأقسام

### 1) لوحة المعلومات (Dashboard)
نظرة عامة على ملف المحرك: إجمالي القواعد، المفعّل منها، توزيع الحالات، حجم
مصفوفة الدمج ومجموعات الأولوية. بيانات وصفية فقط لا تغيّر النتيجة تلقائيًا
(FR-ES-13). وتعرض معها لوحتي **الحوكمة**: التعارضات غير المحسومة المكتشفة
تلقائيًا (مع زر تطبيق الوسم)، وعدد قيود سجل التدقيق وروابط أقسامه.

### 2) القواعد ومنشئها (Rule Explorer + Rule Builder) — FR-ES-02/03/07
- الشروط ثلاث مجموعات: **و** (كلها)، **أو** (يكفي واحد)، **ليس** (لا يجوز
  أحدها). المجموعات المتداخلة الموجودة في قاعدة مستوردة تُحفظ كما هي.
- إجراء `PREVENT_MERGE` له مفتاح **تنافٍ** (`params.exclusive = true`): لا مجرد
  فصل في سطرين بل «لا يُضربان وجهًا»؛ يقرأه المحرر عبر `resolveLocusExclusion`.
- **المستكشف (Rule Explorer — FR-ES-07.1)**: كل القواعد مصنّفة مع بحث وتصفية
  وترتيب، وقائمة طويلة-جاهزة:
  - **الشجرة/الدلاء**: `Global / Surah / Ayah / Local / Reader / Narrator / Path /
    Merge / Difference / Ordering / Exceptions` — تُشتق من النطاق والخصوصية
    ومجموعة الأولوية والفئة وحقول الشروط (لا حقل تصنيف جديد يُخزَّن، فلا يمكن
    أن يختلف التصنيف عن القاعدة نفسها). أولوية التصنيف: الجمهور ← التضييق
    بالنطاق ← الوظيفة ← العام. والفئات الأربع عشرة كلها موزّعة على الدلاء بلا
    ثغرة (مختبر).
  - **البحث**: عربي مطبّع (بلا تشكيل، وهمزات موحّدة) في الاسم والوصف والمعرّف
    والفئة والنطاق والمجموعة وحقول الشروط وقيمها وأسماء حالات الاختبار. كل كلمة
    في البحث يجب أن تظهر (بحث بـ«و»).
  - **التصفية**: الحالة (متعددة)، الفئة (١٤)، الدلو (١١)، مجموعة الأولوية،
    الصلابة، الخصوصية، المصدر (`SYSTEM/EDITOR/CANDIDATE/IMPORTED`)، ومفاتيح
    سريعة: المحمية فقط / بها اختبارات / النافذة فقط / المتعارضة فقط / المعدّلة
    فقط. وتُركَّب بـ«و».
  - **الترتيب**: الأولوية، الاسم (عربيًا)، الحالة (بترتيبها المعرفي)، آخر تعديل،
    الاستخدام (كم قاعدة تشير إليها)، رقم الإصدار، الخصوصية — صعودًا/نزولًا،
    والتعادل يُحسم بالمعرّف فلا يقفز صف بلا سبب.
  - **الأداء**: رأس ثابت، شريط تمرير ظاهر (`scrollbar-gutter: stable`)، مؤشرا
    صعود/نزول، ونافذة عرض (`useWindowedList` من الحزمة ٠٣) ترسم المدى المرئي فقط
    مع حشوات صادقة وقياس فعلي لارتفاع الصفوف. رؤوس المجموعات لاصقة، والصفوف
    تُطوى/تُفتح. مختبر بـ٥٠٠ قاعدة.
  - **من كل قاعدة**: «المحرر ↗» رابط عميق `/editor?rule=<id>&why=1` يفتح المحرر
    ويُبرز القاعدة في أثر القرار على المواضع المتأثرة (FR-ES-15)، و«لماذا؟»
    يفتح الساحة مُعبّأة بنوعي القاعدة، و«الإصدارات» و«الاختبارات» و«الاعتمادات»
    تنقل إلى لوحاتها.
  - **شارات الصف**: الحالة، 🔒 محمية، ⚠ تعارض (مع الأسباب في `title`)، الأولوية،
    `v٣` (عدد إصدارات السلسلة)، عدد حالات الاختبار، وعداد الاستخدام.
- **المنشئ**: إنشاء/تعديل قاعدة بلا كتابة كود:
  - الحقول: الاسم، النوع، الفئة، النطاق، مجموعة الأولوية، الخصوصية، الأولوية
    الرقمية، الصلابة (HARD/SOFT)، الحالة، الحماية.
  - **منشئ الشروط**: صفوف من حقل + معامل + قيمة، مجمّعة بـ AND. الحقول المتاحة:
    نوع الاختلاف، القارئ، الراوي، الطريق، السياق، الموضع... (FR-ES-03).
  - **منشئ الإجراءات**: إجراءات جاهزة تُختار بالنقر (إنشاء اختلاف، دمج، منع
    دمج، فصل، تغيير ترتيب، تجاوز نتيجة، حجب...) (FR-ES-03).
  - **قوالب جاهزة**: قوالب الوقف/الوصل/الابتداء/ممنوع الوصل تملأ المسودة بلا كود
    (FR-ES-16.2): «وقفا عند نهاية الآية: أنشئ اختلافًا»، «وصلا: أنشئ»،
    «ابتداء: أنشئ»، «ممنوع الوصل: احجب».
  - **حالات اختبار**: تُرفق بكل قاعدة وتُشغَّل لاكتشاف الانحدار (FR-ES-08).

### 3) مصفوفة الدمج (Merge Matrix) — FR-ES-05
جدول قابل للتحرير الرسومي يقرر متى يُدمج عنصران (مثل مد+تحقيق) ومتى لا
يُدمجان (مثل فرش+مد)، بأولوية وسبب. البحث غير حساس لترتيب العنصرين، والأعلى
أولوية يفوز عند التعارض. كل قرارات الدمج في المحرر والمحرك تصدر عنها.

- **مطلق / مشروط** (`conditional`): المدخل المطلق يُطبَّق دائمًا ما لم تتعارض
  قواعد الدمج. المدخل المشروط قيمته افتراض فقط؛ متى طابقت قاعدة دمج واحدة
  السياق (وقف/وصل/راوٍ...) حسمت هي القرار حتى بلا تعارض، ويظهر ذلك في الأثر
  بخطوة `CONFLICT` تحمل معرّف القاعدة.

### 4) الأولويات والأنابيب (Priority & Pipeline) — FR-ES-01/04/06
- **مجموعات الأولوية**: السلم الهرمي (بنائية، منع، استثناءات، قرّاء، رواة،
  طرق، اختلافات، دمج، احتياطية).
- **سلم حل التعارض**: يُفعَّل/يُعطَّل بالترتيب (الأخص، الأولوية الأعلى، الصريحة،
  المحلية، القارئ، يدوي). عند تعارض قاعدتين يُجرَّب السلم حتى يُحسم بلا اختيار
  عشوائي.
- **خط أنابيب القرار**: ترتيب التنفيذ (تطبيع ← سياق ← منع ← ... ← ترتيب).
- **إعادة الترتيب بالسحب أو بالأسهم** في الثلاثة: المجموعات (يُعاد إسناد
  `order` = ١..ن)، والقواعد داخل المجموعة (يُعاد ترقيم `priority` بفجوة ١٠
  فيبقى الرقم صريحًا في الملف — P-04)، وسلم التعارض ومراحل التنفيذ. الأدوات
  النقيّة `moveItem`/`renumberPriorities` مختبرة.

### 5) ساحة لماذا؟ ورسم منطق القرار — FR-ES-09/10، FR-ES-07.7.2
اختر عنصرين لمعرفة قرار الدمج مع **أثر كامل**: المراحل، القواعد المطابقة
والفائزة والمتجاهلة وأسبابها. هذا هو «لماذا؟» متاحًا على أي قرار. كل شيء يمرّ
عبر Decision Resolver (لا منطق مكرر).

**Visual Decision Graph**: تحت الأثر مباشرة يُرسم منطق القرار بصريًا:

```
Input ↓ [Condition] ├── نعم → [Rule A] → [Merge] → [Result]
                    └── لا  → [قواعد لم تطابق] ↗
```

الرسم **يقرأ نفس بيانات الأثر** (`DecisionTraceStep[]`) ولا يعيد حساب شيء
(`decision-graph.ts` نقيّة ومختبرة): عُقد `INPUT / CONDITION / RULE / STAGE /
OUTCOME / RESULT` بأعمدة وصفوف محسوبة حتميًا وإحداثيات RTL (المدخل أقصى
اليمين)، وفرعا «نعم/لا» من خطوات `MATCH` نفسها، ومراحل الأثر الأخرى
(`MERGE/CONFLICT/EXCLUSION/...`) كعُقد مسلسلة. القواعد الكثيرة تُطوى في عقدة
«و n قاعدة أخرى» (الحد ٦) والمراحل كذلك (الحد ٤) فلا ينفجر الرسم، والأثر
الكامل يبقى في القائمة فوقه. النقر على عقدة يُبرز مسارها من المدخل، ونقر عقدة
قاعدة يفتحها في المنشئ. SVG داخلي بلا مكتبة خارجية.

ومن المستكشف أو بطاقة القاعدة يمكن إبراز قاعدة في الساحة: تُعبّأ الساحة بنوعي
الاختلاف من شروطها، ويُقال صراحةً هل ظهرت في الأثر أم لا.

### 6) اختبارات القواعد وكشف الانحدار (Rule Tests) — FR-ES-08
لكل قاعدة يمكن إرفاق حالات اختبار (`{ name, input, expected }`) من المنشئ نفسه.
هذه اللوحة تُجريها كلها عبر واجهة القرار الموحّدة (لا منطق مكرر) وتعرض الناجح
والفاشل مع **مؤشر الانحدار**: تغيّر قاعدة فانقلبت نتيجة مرجعية.

- **تشغيل تلقائي قبل الحفظ**: كل تعديل في المنشئ يُشغّل حالات القاعدة (اتحاد
  قبل/بعد) على محرك القرار الحالي عبر `previewRuleEdit`، فتظهر «معاينة الأثر»:
  كم حالة انقلبت وكم ثبتت، وكل حالة منقلبة بصيغة `Expected: SEPARATE / Current:
  MERGE`.
- **بوابة الحفظ**: إن انقلبت حالة مرجعية كانت ناجحة يرتفع إنذار
  **⚠ Regression detected** ولا يُحفظ إلا **بتأكيد صريح بالتجاوز الموثّق**:
  حوار يطلب سببًا مكتوبًا إلزاميًا (٣ أحرف فأكثر)، ويعرض الفرق قبل/بعد
  والعدادات، ويحفظ السبب في إصدار القاعدة وفي سجل التدقيق بقيد
  `REGRESSION_OVERRIDE` موسوم `override: true` (يُصفّى في لوحة التدقيق).
- **قواعد النظام مرجعية**: القواعد الثلاث المشحونة تحمل حالات اختبار مرجعية
  (فرش+مد ← فصل، مد+تحقيق ← دمج، مد+مد ← فصل)، والقاعدتان الصلبتان موسومتان
  محمية.
- **في CI**: `tests/rule-test-suite.test.ts` يُشغّل كل حالات القواعد المرجعية
  **وكل ملف مُودَع في `tests/fixtures/engine-profiles/*.json`** ويفشل عند أي
  انحدار — فـ`npm test` يحرس المحرك مستقبلًا. لإيداع ملفك: صدّره من الاستوديو
  وضعه في ذلك المجلد.
- **عدّاد**: زر «تشغيل وتسجيل في التدقيق» يُشغّل المجموعة ويكتب قيد `TESTS_RUN`
  بالنتيجة الرقمية. والقواعد بلا حالات اختبار تُسرد في ذيل اللوحة.

### 7) قاعدة من تصحيح (Candidate Rules) — FR-ES-12.4، AC-02.4
«أنشئ قاعدة من التصحيح»: يصف المستخدم تصحيحًا (قرار المحرك A ورغبة المحرر B)
فيقترح النظام قاعدة `EngineRule` مرشحة (DRAFT) جاهزة للمراجعة والاعتماد — لا
إنشاء تلقائي (P-06). هذا هو قلب حلقة التعلم (تصحيح ← قاعدة مرشحة ← اختبار ←
اعتماد). المنطق نقيّ في `candidate-rule.ts`، ويكشف أيضًا الأنماط المتكررة من عدة
تصحيحات (FR-ES-12.3).

### 8) مقارنة الملفات (Profile Compare) — FR-ES-11
تقارن لوحة «مقارنة الملفات» الملف الحالي بالملف الافتراضي للنظام على الأزواج
الشائعة، وتصنّف كل موضع: متطابق/متغيّر، ومع مرجع معتمد: متحسّن/متراجع. وتقرّر
ما إذا كان الملف آمنًا للاعتماد (لا تراجع عن المرجع). المنطق نقيّ في
`profile-compare.ts`.

### 9) النشر والسجل (Publish Gate & History) — FR-ES-07/14
- **تشغيل جاف قبل النشر**: يقارن الإعداد الجاري بآخر نسخة محفوظة: سجل التدقيق
  المتوقَّع (قواعد أُضيفت/عُدّلت/حُذفت، مصفوفة، سلم، ترتيب)، القرارات التي
  تتبدّل على المدخلات المرجعية (تحسّن/تراجع)، ونتائج اختبارات القواعد. النشر
  يمرّ بحوار تأكيد كمي ويسمح بملاحظة إصدار.
- **سجل الإصدارات**: كل نشر يلتقط نسخة كاملة مرقّمة مع تدقيق التغييرات
  (`engine-config-history.ts`؛ الحفظ المطابق لا يُكرَّر؛ الحد ٤٠ نسخة).
  **الاسترجاع** يعيد نسخة بعينها إلى الملف الحي عبر نفس مسار الحفظ ويُسجَّل بدوره؛
  لا شيء يُمحى. **تجاهل التغييرات** يعود لآخر محفوظ.
- الاستيراد لا يُنشر تلقائيًا: يبقى «غير محفوظ» حتى يمرّ بالبوابة.

### 10) التصدير والاستيراد (Export/Import) — FR-ES-14
- **تصدير حتمي صديق لـ Git**: نفس الإعداد يعطي نفس النص بايتًا، فيظهر Git
  فرقًا دقيقًا (`Rule A priority: 80 → 100`) لا فرقًا فوضويًا (DM-13).
- **استيراد بفحص**: السلامة، توافق الإصدار، كشف التعارض (المعرّفات المكررة)،
  مع معاينة الأخطاء قبل التطبيق.

### 11) بطاقة القاعدة: Metadata + دورة الحالة + الإصدارات — FR-ES-07.2/.3/.4/.5
تظهر تحت المنشئ للقاعدة المحددة، ثلاث لوحات:

**أ) Metadata كاملة** — كل حقل من FR-ES-07.4: `ID, Name, Description, Category,
Scope, Priority, Specificity, Status, Source, CreatedAt, UpdatedAt, Version,
Dependencies, Overrides, Conflicts, TestCases`، مع دلو المستكشف ومجموعة الأولوية
والصلابة، و**عدادات الاستخدام الخام** (كم قاعدة تعتمد عليها/تتجاوزها/تعلن
تعارضها، وكم قاعدة تُطلقها أو تُطلَق منها) — تُشتق من الملف فلا تُخزَّن مرتين.
الإحالات المعلنة تُعرض بأسمائها، والمشتقة من بنية الشروط والإجراءات بوسم
«(مشتقة)»، وكل منها نقّال إلى قاعدته.

**ب) دورة الحالة (Rule Status)** — الانتقالات **المحكومة** فقط، معروضة من الحالة
الحالية، وكل انتقال يبيّن وسمه: `يعتمد بتأكيد` / `سبب إلزامي` / `يغيّر سلوك
المحرك` / `قاعدة محمية`.

| من | إلى | الشرط |
|---|---|---|
| Draft | Active | اعتماد صريح (تأكيد) |
| Draft | Experimental / Disabled | — |
| Experimental | Active | اعتماد + سبب إلزامي |
| Experimental | Draft / Disabled | — |
| Active | Disabled | تأكيد + سبب إلزامي |
| Active | Deprecated | تأكيد + سبب إلزامي (إيقاف موثّق، **بلا حذف تاريخي**) |
| Active | Conflicted | سبب (يدويًا، والتلقائي من الكشف) |
| Disabled | Active | اعتماد |
| Disabled | Deprecated | تأكيد + سبب |
| Deprecated | Disabled | تأكيد + سبب (لا رجوع مباشرًا للتفعيل: يمرّ بالتعطيل) |
| Conflicted | Active / Disabled / Draft | تأكيد + سبب (حسم التعارض) |

ما ليس في الجدول ممنوع (`canTransition`)، والرفض يُعلَّل للمستخدم لا بصمت.
و**الوسم التلقائي**: عند اكتشاف تعارض غير محسوم بسلم السياسة (تعادل أولوية
وخصوصية وصلابة بين قاعدتين متناقضتين، أو تعارض مُعلن بين قاعدتين نافذتين) تُعرض
القواعد المعنية بلون تحذيري في المستكشف والبطاقة، وزر «تطبيق وسم التعارض» يكتب
الحالة `CONFLICTED` موثّقة (ويُرفع الوسم تلقائيًا حين يُحسم التعارض). الكشف
مستمر وعابر (`syncConflictTags` مستقرة لا تتذبذب)، والكتابة صريحة بيد المستخدم.

**ج) سلسلة الإصدارات (Versioning)** — خط زمني v١ ← v٢ ← v٣ لكل إصدار:
`Created` (الوقت)، `Modified` (مصدر التغيير: إنشاء/تعديل/حالة/أولوية/حماية/رجوع/
استيراد)، `By` (المنفّذ)، `Reason` (السبب)، ولقطة كاملة قابلة للفك (JSON).
ومقارنة **فرق بين إصدارين** بحقول القاعدة (نفس فرق الحقول الذي يُحفظ في
التدقيق ويُرى في ملف التصدير الحتمي). و**الرجوع الموثّق**: يُنشئ إصدارًا جديدًا
بمحتوى الإصدار المستهدف (`rollbackOf`) **ولا يحذف الإصدارات الوسيطة**، بسبب
إلزامي. بلا حد أعلى للإصدارات، مع تنبيه حجم بعد ٥٠ (بلا حذف تلقائي).

**القاعدة المحمية (Protected Rule)**: وسم 🔒 في المستكشف والبطاقة، ولا تغيير ولا
حذف إلا بتأكيد إضافي صريح **بسبب مكتوب إلزامي** يُحفظ في الإصدار والتدقيق.
رفع الحماية نفسه هو الاتجاه الحسّاس فيطلب سببًا. والحذف يُزيل القاعدة من الملف
**وتبقى سلسلة إصداراتها**، فيظهر في سجل التدقيق زر «استرجاع» يعيدها من آخر
إصدار بحالة `DISABLED` (لا تُفعَّل صامتة).

### 12) سجل التدقيق (Audit Trail) — FR-ES-07.6
كل تعديل في Engine Studio يُسجَّل: `User, Action, Rule, Before, After, Reason,
Timestamp`. الأفعال: إنشاء/تعديل/تغيير حالة/تغيير أولوية/تغيير حماية/رجوع/حذف،
وسم تعارض ورفعه، تشغيل اختبارات، تجاوز انحدار، ونشر/استيراد/استرجاع/إعادة ضبط
الملف.

- **طريق واحد للتغيير**: كل تعديل يمرّ `rule-governance` فيلتقط إصدارًا ويكتب
  قيدًا — لا تستطيع لوحة أن تعدّل بلا أثر (P-07).
- **التصفية**: بالمنفّذ، والفعل (شارات بعدّادات)، والقاعدة، والمدى الزمني، ونص
  البحث، و«التجاوزات الموثّقة فقط». وكل قيد يُفتح لعرض قبل/بعد لكل حقل.
- **من «User»؟** `local-editor` افتراضيًا حتى تفعيل المصادقة؛ الحقل `actor` جاهز
  فلا يلزم ترحيل.
- **القائمة طويلة-جاهزة** بنافذة عرض، والأفعال الخطِرة بلون تحذيري.
- **يدخل التصدير** ضمن حزمة الحوكمة (أدناه)، والحد ٥٠٠ قيد يُطوى الأقدم منها.

### 13) رسم اعتمادات القواعد (Dependency Graph) — FR-ES-07.7.1
رسم عُقدي SVG قابل للتنقل يعرض لكل قاعدة الأنواع الأربعة:

| النوع | المصدر |
|---|---|
| **Depends On** | `dependsOn` المعلَن |
| **Overrides** | `overrides` المعلَن |
| **Conflicts With** | `conflictsWith` المعلَن (متناظر — يُرسم في الاتجاهين) |
| **Triggers** | مشتق: إحالة إجراء إلى معرّف قاعدة (`params.ruleId`/`targetRuleId`/…)، أو إجراء يكتب حقلًا (`params.field/set/assign/context`) تقرأه شروط قاعدة أخرى |

الخط المتصل = علاقة معلنة، والمتقطّع = مشتقة من البنية. التخطيط طبقي حتمي
(العمود ٠ أقصى اليمين في RTL)، مع تكبير/تصغير وسحب، ومرشّح لأنواع الحواف،
ونقر عقدة يُبرز جيرانها ويُظهر جدولا بالأنواع الأربعة (منها/إليها)، ونقر مزدوج
يفتح القاعدة. **كشف الدورات** يظهر تحذيرًا (A ← B ← A)، والقواعد المعزولة
تُعدّ وتُرسم باهتة. و«التركيز» يرسم رسمًا جزئيًا حول القاعدة بعمق الجيران
المطلوب.

## حزمة الحوكمة (Governance Bundle)

التصدير العادي يبقى **ملف الإعداد** وحده (`schemaVersion: 1` بلا تغيير، فلا
يُكسر أي ملف مُصدَّر سابق). وللتدقيق الكامل تُصدَّر **حزمة حوكمة** مستقلة:

```jsonc
{
  "format": "tashjeer-engine-governance",
  "bundleVersion": 1,
  "exportedAt": "…",
  "config": { /* ملف الإعداد الكنسي نفسه */ },
  "ruleVersions": [ /* كل الإصدارات: ruleId، version، at، by، source، reason، rollbackOf، rule */ ],
  "auditTrail":   [ /* كل القيود: id، at، actor، action، ruleId، summary، reason، changes */ ],
  "testReport":   { "total": 0, "passed": 0, "failed": 0, "failingRuleIds": [] }
}
```

حتمية كملف الإعداد (DM-13): الإصدارات مرتبة بالمعرّف ثم الرقم، والتدقيق بالوقت
ثم المعرّف، ومفاتيح اللقطات مرتبة أبجديًا — نفس المدخلات تعطي نفس النص بايتًا.
والاستيراد يقبل **الصيغتين** ويميّزهما تلقائيًا (`detectStudioImport`): ملف
مجرد يُطبَّق كإعداد، وحزمة تعيد الإعداد **مع السجلين** (جولة كاملة مختبرة).

**لماذا حزمة مستقلة ولا يُدمج السجل في `EngineConfig`؟** لأن تضمينه في لقطة كل
إصدار من إصدارات الملف يجعل التخزين تربيعي النمو (٤٠ نسخة × ن قيدًا) ويكسر
قاعدة «الحفظ المطابق لا يُكرَّر». القرار موثّق في `PROGRESS.md`.

## ملفات المحرك (Profiles)

النظام يبدأ بـ `default` (سياسات النظام الحالية). الطريق إلى ملفات متعددة
(Default/Experimental/Testing/Legacy/Reference) ومقارنتها (FR-ES-11) مُعدّ
بنيويًا عبر حقل `profile`، وواجهة التبديل والمقارنة من الخطوات اللاحقة.

## سير الاعتماد

```
Draft → Test (ساحة لماذا؟ + حالات الاختبار) → Preview (معاينة الأثر) → Approve → Active
                                                                          ↓
                                     Disabled ⇄ Active        Deprecated (إيقاف موثّق، لا حذف)
                                                                          ↓
                              Conflicted (وسم تلقائي عند تعارض غير محسوم) → Active بعد الحسم
```

قاعدة جديدة تُنشأ بحالة `DRAFT` لا تؤثر حتى تُفعَّل. والتفعيل والعزل (Active →
Deprecated) موثَّقان بإصدار جديد وسبب وقيد تدقيق (FR-ES-07.2/.3). وكل حفظ —
ولو لم يغيّر حالة — يمرّ `rule-governance`: إصدار إن كان هناك فرق فعلًا، وقيد
تدقيق دائمًا.

✅ مجموعات الأولوية وسلم التعارض · ✅ خط أنابيب القرار · ✅ ساحة لماذا؟ وأثر
القرار · ✅ قاعدة من تصحيح (FR-ES-12) · ✅ مقارنة الملفات وأمان الاعتماد
(FR-ES-11) · ✅ معاينة أثر تعديل قاعدة قبل الحفظ (FR-ES-09.4) · ✅ فحص الملف
وكشف التعارضات والتصادمات (FR-ES-07/13) · ✅ التصدير والاستيراد بفحص.

## ما أُضيف في الحزمة ١١ (PH10a)

- **مستكشف قواعد شامل**: دلاء تصنيف مشتقة (١١) متكاملة مع الفئات (١٤)، بحث عربي
  مطبّع، تصفية بسبعة أوجه وخمسة مفاتيح سريعة، سبعة مفاتيح فرز حتمية، ونافذة
  عرض لقوائم ٣٠٠+ قاعدة (FR-ES-07.1).
- **دورة حالة محكومة** بجدول انتقالات صريح، واعتماد وسبب إلزامي، ووسم
  `CONFLICTED` التلقائي عند تعارض غير محسوم مع رفعه عند الحسم (FR-ES-07.2).
- **إصدارات لكل قاعدة** (v١ ← v٢ ← v٣) مع Created/Modified/By/Reason، فرق بين
  إصدارين، ورجوع موثّق يُنشئ إصدارًا جديدًا بلا حذف وسيط (FR-ES-07.3).
- **Metadata كاملة** + عدادات استخدام خام مشتقة (FR-ES-07.4)، **قواعد محمية**
  بتأكيد إضافي وسبب إلزامي، وحذف يسترجع من السلسلة (FR-ES-07.5).
- **سجل تدقيق** لكل تعديل (User/Action/Rule/Before/After/Reason/Timestamp) قابل
  للتصفية، وطريق تغيير واحد يمرّ الحوكمة كلها (FR-ES-07.6).
- **رسم اعتمادات** عُقدي (Depends On/Overrides/Conflicts With/Triggers) بكشف
  الدورات، و**رسم منطق القرار** من بيانات الأثر نفسها (FR-ES-07.7).
- **بوابة انحدار**: تشغيل تلقائي لاختبارات القاعدة قبل الحفظ، إنذار
  `Regression detected` بفرق `Expected/Current`، وتجاوز موثّق بسبب إلزامي؛
  و`npm test` يشغّل كل الحالات المرجعية والملفات المُودَعة فيفشل عند الانحدار
  (FR-ES-08).
- **حزمة حوكمة** حتمية للتصدير/الاستيراد (الإعداد + الإصدارات + التدقيق +
  ملخّص الاختبارات) مع تمييز الصيغتين تلقائيًا (FR-ES-08.3، DM-13).
- قاعدة صريحة تناقض مصفوفة الدمج تُعرض على **سلم حل التعارض نفسه** فيظهر الحسم
  في الأثر بدل أن يحدث بصمت — وهو ما يجعل لقواعد الاستوديو أثرًا حقيقيًا وللاختبارات
  المرجعية معنى (FR-ES-05/06).

## ما أُضيف بعد PH1

- الترتيب بالسحب للمجموعات والقواعد وسلم التعارض ومراحل الأنابيب (FR-ES-01/04/06).
- مجموعات «أو/ليس» ومفتاح التنافي (FR-ES-03).
- مدخلات مصفوفة مشروطة (FR-ES-05).
- سجل الإصدارات والاسترجاع والتدقيق وبوابة النشر بتشغيل جاف (FR-ES-07/09/14).
- الربط الثنائي مع المحرر: روابط عميقة في الاتجاهين، «لماذا؟» لكل سطر، أثر
  القرار في صفوف التتبع، و«قاعدة من هذا التصحيح» من ثلاثية التصحيح (FR-ES-15).

## ما يلي (الحزمة ١٢)
