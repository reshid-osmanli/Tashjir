# توثيق المحرر - Editor Documentation

> المرجع الكامل لمحرر التشجير: نموذج البيانات، محركات الحساب، المكونات، وطريقة العمل.

---

## 1. لماذا أُعيد بناء المحرر؟

المحرر في النسخة الأولى كان يرسم خطوطا حرة مرتبطة بـ `qiraahId` رقمي. هذا التصميم فيه ثلاث مشكلات منهجية:

| المشكلة | الأثر |
|---------|-------|
| الخط مرتبط براو واحد | الحكم الذي يقرأ به 19 راويا يحتاج 19 خطا مكررا |
| الرسم يدوي بالكامل | المحرر يرسم شكلا، ولا يسجّل معلومة قابلة للتحقق |
| لا وجود للدليل ولا للنطاق | لا يمكن مراجعة العمل علميا |

النسخة الحالية تقلب المعادلة: **المستخدم يسجّل الاختلاف، والمحرك يرسم الخطوط.**

## 2. نموذج البيانات

الملف: `src/types/tashjeer.ts`

```
TashjeerDocument (مستند آية واحدة)
├── variants: Variant[]           ← الاختلافات المسجّلة
│   └── alternatives: VariantAlternative[]   ← أوجه الاختلاف
│       ├── scope: ReadingScope   ← من يقرأ بهذا الوجه
│       └── evidences: VariantEvidence[]     ← الأدلة
├── branches: TashjeerBranch[]    ← الخطوط (مولّدة تلقائيا)
├── lineOrder?: string[]          ← ترتيب أسطر يدوي يسبق ترتيب المحرك (v7)
├── links?: TashjeerLink[]        ← روابط المحرر: أوجه مركبة ودمج أسطر وربط أجزاء (v7)
├── segments?: LineSegment[]      ← أجزاء الأسطر: Line→Segment→Rule (v7)
├── editLog?: DocumentEditEntry[] ← سجل التصحيحات اليدوية قبل/بعد (v7)
└── meta: DocumentMeta            ← التوثيق وحالة المراجعة
```

### 2.1 الاختلاف (Variant)

موضع في الآية تختلف فيه القراءة. له:

- **فئة** (`category`): أصول، فرش، مدود، همز، وقف، تجويد.
- **مدى كلمات** (`startPosition` .. `endPosition`) بترقيم 1-based داخل الآية.
- **أوجه** (`alternatives`): وجه واحد منها هو `isBase` أي نص المصحف المطبوع.
- **حالة** (`status`): مسودة، قيد المراجعة، معتمد، مرفوض.

### 2.2 الوجه (VariantAlternative)

نص معيّن يقرأ به نطاق معيّن. الوجه المعلَّم بـ `isBase: true` **لا يُرسم له خط**، لأنه هو النص المكتوب على اللوحة أصلا (رواية حفص).

### 2.3 النطاق (ReadingScope)

هذا هو حل مشكلة التكرار. بدل تخزين الحكم لكل راو، نخزّنه مرة واحدة مع تعبير عن مجموعة القرّاء:

| النوع | المعنى | مثال |
|-------|--------|------|
| `ALL` | الرواة العشرون | حكم متفق عليه |
| `ALL_EXCEPT` | الجميع إلا المذكورين | `عليهم` بالكسر: الجميع إلا حمزة ويعقوب |
| `IMAMS` | كل رواة أئمة معيّنين | `عاصم` = حفص وشعبة |
| `NARRATORS` | قائمة رواة صريحة | ورش والسوسي وابن وردان |
| `PATHS` | طرق محددة | طريق الأزرق عن ورش |

الملف: `src/lib/tashjeer/scope.ts`

**دالة `normalizeScope`** تختصر أي قائمة رواة إلى أبسط تعبير تلقائيا:

```ts
normalizeScope(['narrator-hafs', 'narrator-shubah'])
// → { kind: 'IMAMS', imamIds: ['imam-asim'] }

normalizeScope(كل الرواة عدا حفص)
// → { kind: 'ALL_EXCEPT', narratorIds: ['narrator-hafs'] }
```

**دالة `describeScope`** تبني وصفا عربيا للعرض على بطاقة الوجه:

```ts
describeScope({ kind: 'IMAMS', imamIds: ['imam-asim'] })  // "عاصم بكماله"
describeScope({ kind: 'ALL_EXCEPT', narratorIds: [حفص] }) // "الجميع إلا حفص"
```

## 3. المحركات

### 3.1 محرك التخطيط (`layout-engine.ts`)

يحوّل كلمات الآية إلى صناديق (`WordBox`) لها إحداثيات دقيقة.

**لماذا لا نقيس بالمتصفح؟** لأن المحرر يجب أن يعطي نفس الناتج على الخادم (SSR) وفي الاختبارات. فالقياس بنموذج رياضي حتمي:

```ts
measureWordWidth('ٱلرَّحِيمِ', 34)  // نفس القيمة دائما
```

**قواعد القياس:**

- كل حرف له معامل عرض نسبي لحجم الخط (`LETTER_WIDTH_RATIO`).
- الحركات والتنوين والسكون والشدة وعلامات الوقف **عرضها صفر**، لأنها تُرسم فوق الحرف أو تحته.
- الألف الخنجرية (`U+0670`) عرضها صفر كذلك: `مَٰلِكِ` أضيق من `مَالِكِ`.
- الاتجاه من اليمين لليسار: نبدأ من `canvasWidth - paddingRight` ونتقدم يسارا.
- الالتفاف تلقائي عند بلوغ الهامش الأيسر.

كل صندوق يعطي ثلاث نقاط ارتباط: `topY` (للأصول) و`bottomY` (للفرش) و`centerX`.

### 3.2 محرك التشجير (`branch-engine.ts`)

قلب المشروع. يحوّل الاختلافات إلى خطوط مرسومة، وفق أربع قواعد منهجية:

#### القاعدة 1: وجه المصحف لا يُرسم

```ts
if (alternative.isBase) continue;
```

#### القاعدة 2: توزيع المناطق

| الجهة | الفئات | السبب |
|-------|--------|-------|
| فوق النص | أصول، مدود | أحكام عامة مطّردة في نظائرها |
| تحت النص | فرش، همز، وقف، تجويد | مواضع جزئية مرتبطة بكلمة بعينها |

#### القاعدة 3: الترتيب من آخر الآية إلى أولها

القاعدة المعتمدة في المشروع: يُقرأ الاختلاف من آخر الآية إلى أولها. لذلك الخط الذي تبدأ عقدته في موضع **متأخر** يأخذ مسارا **أقرب إلى النص**:

```ts
if (aStart !== bStart) return bStart - aStart;  // الأكبر موضعا أولا
```

#### القاعدة 4: تعبئة المسارات (Lane Packing)

خطان لا يتقاطعان أفقيا يتشاركان نفس المسار. هذه خوارزمية تلوين مخطط فترات (interval-graph coloring) مبسطة، تقلّل ارتفاع اللوحة كثيرا في الآيات المزدحمة:

```
اختلاف في الكلمة 1  ──────┐
                          ├─ نفس المسار (لا تداخل)
اختلاف في الكلمة 8  ──────┘

اختلاف 1..5  ─────┐
                  ├─ مساران منفصلان (متداخلان)
اختلاف 3..7  ─────┘
```

#### الشكل الهندسي للخط

من نقطة الارتباط بالكلمة، منحنى تربيعي قصير إلى المسار الأفقي، ثم سير على المسار، ثم بطاقة الوجه في الطرف الأيسر. الكلمات الوسيطة تُربط بخطوط عمودية قصيرة.

### لماذا SVG وليس Canvas؟

- النص العربي يُرسم بخط المصحف مع تشكيله دون معالجة يدوية للحروف.
- كل عنصر قابل للتحديد والاختبار والتصدير.
- التكبير متجهي لا يفقد الدقة.

### محدد النطاق (ScopePicker)

أهم عنصر في `VariantEditor`. يعرض القراء العشرة، وتحت كل واحد راوييه. النقر على اسم الإمام يختار رواته كلهم. لون كل إمام ثابت، فرواة الإمام الواحد يشتركون في اللون.

بعد كل تغيير يُستدعى `normalizeScope` تلقائيا، فلا يخزَّن "حفص + شعبة" بل "عاصم".

## 5. الحالة والتخزين

### 5.1 مخزن المحرر (`stores/editor-store.ts`)

**مبدأ التراجع:** يعمل على المستند نفسه لا على حالة الواجهة.

- تعديل حقيقي (إضافة اختلاف، حذف وجه) → تُسجَّل لقطة كاملة للمستند.
- تغيير عرض (تكبير، فتح لوحة) → **لا** تُسجَّل لقطة.

السبب: المستخدم لا يتوقع أن يتراجع `Ctrl+Z` عن تكبير الشاشة.

**إعادة التوليد:** بعد أي تعديل على الاختلافات، تُعاد الخطوط تلقائيا عبر `generateBranches`، مع الحفاظ على الخطوط المعلَّمة `isManual`.

### 5.1.1 سياق التحديد الموحّد (FR-ED-02) — بروتوكول اللوحات

«العنصر المحدد الآن» حقل واحد (`selection`) في مخزن المحرر، تقرأه وتكتبه كل
اللوحات: لوحة الرسم، قائمة الاختلافات، لوحة الخصائص، العلاقات (أوجه/أسطر/
أجزاء/ترتيب)، التتبع، والاستوديو. لا تملك أي لوحة تحديدًا محليًا مناقضًا.

**الأنواع المدعومة:** كلمة، حرف، موضع (Locus)، سطر، جزء، اختلاف، وجه، قاعدة
(عامة/استوديو)، وجه مركب، علامة وقف — النوع في `types/tashjeer.ts`
(`EditorSelectionKind`)، والوصف والسلسلة في `lib/tashjeer/selection-context.ts`.

**الكتابة الموحّدة:**

- اللوحات تستدعي `selectElement(selection, { center? })` من
  `lib/editor/selection-store.ts` (أو إجراءات `selectVariant/selectLine/…`
  في المخزن — كلها تمر من الكاتبة المركزية `selectionWrite`).
- كل كتابة ترفع **طلب تركيز** برقم متزايد (`selectionFocus.token`) وتُحدِّث
  `lastSelection` (آخر تحديد صالح). التحديد حالة واجهة: لا يدخل المستند ولا
  التصدير ولا التراجع.

**الاستهلاك في اللوحة (≤ 300ms، AC-06):** عند كل طلب تركيز تبحث اللوحة عن
العنصر بمحدّد `selectionTargetSelector` (سمات `data-*` التي يرسمها
`TashjeerFigure`)، فإن كان خارج الإطار حُرّكت إليه (بلا تغيير تكبير)، أو
وُضع في منتصف الرؤية إن طُلب `center`، ثم نُبض العنصر — الأداة (الاختلاف/
الوجه) **هي بالذات** لا سطرها كله — وتظهر بطاقة معلومات مصغرة أعلى اللوحة.
الحساب النقي (`isRectOutsideViewport`، `computeFocusPan`) مختبر في
`tests/selection-focus.test.ts`.

**الاتجاه العكسي:** تحديد عنصر داخل اللوحة يميّزه في كل اللوحات المفتوحة
(قائمة الاختلافات تمرّر إليه في منتصف الرؤية، وصفوف الترتيب والعلاقات
تتوهج بلون التحديد).

**اللغة البصرية الموحّدة:** لون التحديد زمردي (`--tashjeer-select` + صف
`.selection-row-active`)، ولون التوجيه (Hover/Focus) كهرماني
(`.selection-row-focus`) — معرَّفة في `globals.css` فلا لوحة تخترع لونًا.

**عنصر محذوف:** يُنظَّف التحديد بأمان إلى null مع إبقاء `lastSelection`
لسلسلة سياق رمادية في الشريط العلوي ولوحة التفاصيل.

**قائمة السياق:** الزر الأيمن على أي عنصر (في اللوحة أو القوائم) يفتح
`SelectionContextMenu` بأوامر ممكَّنة من `lib/tashjeer/selection-commands.ts`
(نسخ/قص/لصق/حذف/ترتيب/نسخ المعرّف…)، وتُعرض الأوامر نفسها في لوحة تفاصيل
العنصر (`SelectionDetailsPanel` أعلى لوحة الخصائص) مع المعرّف والرتبة
والآية والصفحة والقواعد والعلاقات والأجزاء والمصدر وحالة التصحيح.

**القوائم الطويلة (FR-ED-01/NFR-01):** كل قوائم المحرر تستعمل الغلاف
`components/ui/ScrollableList`: رأس ثابت، شريط تمرير مرئي دائمًا عند
التجاوز، زرا صعود/نزول عائمان في طرف القائمة (نقرة = خطوة، ضغط مستمر =
تمرير متواصل)، زر «إلى أعلى القائمة»، تمرير بالعجلة واللمس والأسهم، وتنافذ
(Virtualization) أو تحميل تدريجي للقوائم 1000+ — النواة الحسابية في
`hooks/windowed-list-core.ts` مختبرة على 2000 عنصر
(`tests/windowed-list-performance.test.ts`).

تغطية القوائم: قائمة الاختلافات (`VariantsPanel` — بحث فوري بالنص/الفئة/
المصدر/الحالة + تنافذ)، العلاقات والأجزاء (`RelationsPanel`)، ترتيب الأسطر
(`LineOrderEditor` — رأس ثابت وأزرار تمرير مع حفظ سحب الإزاحة الدقيقة)،
سجل تتبّع مواضع القاعدة (`RuleOccurrenceReview` ← تبويب السجل)، فهرس
القواعد والاختلافات (`RulesIndexDialog`)، وقائمة قواعد الاستوديو
(`RuleExplorer`).

**عقد التمركز الدقيق:** منتج الصفوف يضع على كل صف سمة `data-list-index`
بفهرسه في القائمة المرئية (ويقيس ارتفاعه عبر `range.measure`)، فتتمكن
`ScrollableList.scrollToIndex` من وضع الصف المطلوب في **منتصف** منطقة
الرؤية بموضعه المقيس لا بتقديره؛ وإن كان الصف خارج النافذة المرسومة تقفز
القائمة بالتقدير فورًا ثم تعيد التمركز الدقيق حين يرسمه التنافذ (محاولات
محدودة داخل ميزانية الـ 300ms). حاوية التمرير تحمل `data-scroll-viewport`
ليكتشفها منطق خارجي يحتاج التمرير أثناء تفاعل خاص (كسحب الترتيب في
`LineOrderEditor`). عقد الرسم النصي للقائمة محروس في
`tests/scrollable-list-render.test.ts`.

### 5.2 مخزن المستندات (`lib/storage/document-store.ts`)

التخزين محلي في `localStorage` بقرار من صاحب المشروع، حتى يستقر أساس المحرر.

**واجهة مغلقة عمدا:** لا يتعامل أي مكوّن مع `localStorage` مباشرة. عند الانتقال إلى Prisma تُستبدل أربع دوال فقط:

```
loadDocument / saveDocument / listDocuments / deleteDocument
```

دون تعديل أي مكوّن في المحرر.

**صيغة المفتاح:** `tashjeer:doc:v2:{ayahKey}`
**إصدار المخطط:** `schemaVersion` داخل كل مستند يسمح بالترقية التدريجية عبر `migrateDocument`.

**التصدير والاستيراد:** ملف JSON بصيغة `tashjeer-export`، صالح للمشاركة للمراجعة أو للنسخ الاحتياطي.

## 6. سير العمل في المحرر

```
1. اختر السورة والآية من شريط التنقل (أو ابحث في المصحف كله)
2. فعّل أداة التعليم (M)
3. انقر على الكلمة أو الكلمات التي فيها الاختلاف
4. اختر الفئة (أصول / فرش / مدود ...) ثم "إنشاء الاختلاف"
5. في نافذة التحرير:
   - اضبط العنوان والشرح والمرجع
   - أضف وجها: نصه، وصفه، ومن يقرأ به
   - سجّل الأدلة من النشر أو الطيبة
6. المحرك يرسم الخطوط تلقائيا فور الحفظ
7. راجع النتيجة، ثم Ctrl+S للحفظ
8. ارفع حالة المستند إلى "قيد المراجعة"
```

### 6.0 المعالج الذكي الموحّد (FR-ED-08 · FR-ED-09) — باب الإنشاء الواحد

المعالج (`SmartCreateWizard`، الاختصار `N`) هو **باب الإنشاء الواحد** في
المحرر (T3): «إنشاء اختلاف» و«الإنشاء السريع» و«التعميم» مداخل له لا شاشات
منفصلة. يُفتح من تحديد قائم أو من زر «إنشاء ذكي» العام — والتحديد البصري
متاح داخله فلا يُشترط تعليم مسبق. القدرة القديمة كلها باقية: الإنشاء
المفرد صار قالب إنشاء سريع، وإنشاء كل موضع صار وضع «تكرار البنية لكل
هدف»، والمنشئ الصرفي الكامل يُفتح من الخطوة ٦ مزروعًا بإعداد المعالج.

خطواته السبع:

1. **التحديد البصري**: الآية نفسها داخل المعالج بخط المصحف. نقرة للكلمة
   الأولى ونقرة للأخيرة فيُثبَّت مدى «كلمة ← كلمة» قبل الإنشاء — بلا أرقام
   يدوية. وCtrl+نقر يضيف كلمات متفرقة أهدافًا، وتحديد الحروف متاح داخل
   المعالج (الحرف يضم تشكيله؛ المتباعد أهداف إضافية تلقائيًا). مع عدة
   أهداف يُختار: **تكرار البنية لكل هدف** (الإسناد الدفعي FR-ED-09) أو
   **موضع مركّب واحد** (`loci`).
2. **الأنواع**: checkboxes لوجه واحد أو عدة أوجه في العملية نفسها
   (تحقيق/أصول/فرش/مدود…)، وكل نوع كيان مستقل برتبته الصريحة — لا عودة
   لإعادة التحديد لكل وجه.
3. **الأوجه**: أسماء الأوجه سطرًا سطرًا لكل نوع، مع **نص الوجه المقروء**
   و**درجة قوته** من سلّم الدرجات — كل وجه كيان مستقل برتبته.
4. **القرّاء**: محدد النطاق نفسه في `VariantEditor` (نقر على الأئمة/الرواة/
   الطرق مع الاختصار التلقائي).
5. **العلاقات**: «مرتبط» أو «متنافٍ» أو «لكل هدف» (ومعه «جزء من»
   البنيوية PART_OF) أو بلا علاقات — مع **اقتراح السياسة من Resolver**
   وسببه لكل زوج، والمستخدم يعدّل؛ لا علاقات خفية. والقرار يمر عبر
   Resolver: ما وافق الاقتراح يبقى رابطًا بنيويًا مرجعيًا، وما خالفه
   يُوثَّق علاقة يدوية بـCorrection تسبق السياسة في محرك التراكيب فلا
   تبقى علاقة معروضة بلا أثر — وتُعدَّد المخالفات في شاشة المراجعة قبل
   الإنشاء.
6. **النطاق الجغرافي**: هذا الموضع فقط / **هذه الآية كلها** (إنشاء مباشر
   على كل المواضع المطابقة للنمط الحتمي فيها بلا قاعدة، مع عدّ فوري لآية
   واحدة) / مدى آيات / السورة / المصحف كله — والثلاثة الأخيرة قواعد عامة
   مستقلة لكل نوع برتبها (`تحقيق=١، أصول=٢، فرش=٣`) في عملية ذرية واحدة.
   النمط حتمي من الحروف أو من الكلمات كاملة (بلا تحليل نحوي احتمالي)،
   مع سياسة ضبط ونطاق بحث وتوسيع الحروف إلى مجموعات (كحروف الإخفاء)،
   و**معاينة Dry-run غير حاجبة** عند التعميم: فحص سورةً سورة مع مؤشر
   تقدم وإلغاء وعدد المواضع المتطابقة والمتخطاة — قبل التنفيذ. والأنماط
   الصرفية/النحوية المتقدمة في «المنشئ الكامل» بالزر نفسه.
7. **السياق والمراجعة**: وقفًا ووصلًا / وقفًا فقط / وصلًا فقط — للمجموعة
   مع تجاوز مستقل لكل نوع — ثم ملخص عددي (اختلافات/أوجه/علاقات/أهداف/
   مواضع التعميم + تنبيه التصحيحات الموثقة) وزر **إنشاء** الذري بدفعة
   تراجع واحدة.

**القوالب والإنشاء السريع**: قوالب مدمجة (مد + تحقيق + صلة، مد منفصل،
فرش مع أصول، أوجه الوقف، همز) تعبّئ الإعداد بنقرة؛ وزر «حفظ الإعداد
الحالي قالبًا» يحفظ إعدادك مسمى (`tashjeer:wizard-templates:v1`) فيُعاد
من المعالج أو من شرائح ⚡ الإنشاء السريع في لوحة الاختلافات — بنقرة عبر
نواة المعالج نفسها. **الوضع المتقدم** (يُحفظ في التفضيلات) يتخطى الخطوات
المكتملة الافتراضية: من الأنواع إلى المراجعة مباشرة.

**سيناريوهات**:

- *كلمة تحتاج مدًا وتحقيقًا وصلة وفرشًا*: علّم الكلمة (أو افتح المعالج
  وحددها بداخله) ← قالب «مد + تحقيق + صلة» ← راجع ← إنشاء. عملية واحدة
  بدل: أنشئ المد ← أنشئ التحقيق ← ارجع ← حدد ← ادمج ← كرر.
- *الحكم نفسه في أربع كلمات*: علّمها (M أو Ctrl+نقر) ← المعالج ← «تكرار
  البنية لكل هدف» ← إنشاء. أربع نسخ مستقلة بعلاقاتها، وتراجع واحد
  يزيلها كلها.
- *تعميم ثلاثة أنواع على المصحف*: الخطوة ٦ ← المصحف كله ← Dry-run يعرض
  العدد ← إنشاء. ثلاث قواعد مستقلة برتبها، ذريًا.
- *الحكم نفسه في كل مواضع الآية*: الخطوة ٦ ← «هذه الآية كلها» ← يظهر عدد
  المواضع المطابقة فورًا ← إنشاء. البنية تُولد على كل موضع مطابق في
  معاملة واحدة بلا حفظ أي قاعدة عامة، وتراجع واحد يزيلها كلها.

تقنيًا: كل الإنشاء المباشر (موضع/آية) يمرّ عبر `buildSmartCreateBatch` /
`buildSmartCreateMultiTargetBatch` ثم `applySmartCreateBatch` — معاملة
واحدة للتراجع، وعلاقات بمعرّفات الكيانات، لا هياكل خاصة بالواجهة.
والتعميم عبر `saveGlobalRulesBatch` الذري (تحقق من الكل ثم كتابة واحدة).
وعلاقات التنافي/الارتباط المخالفة لاقتراح السياسة تُوثَّق في
`applySmartCreateBatch` نفسه عبر `resolveLocusRelation` (رابط
`DIFFERENCE_TO_DIFFERENCE` + Correction — حزمة 05/T2) فلا يتفرق قرار
التنافي. منطق النقر (`nextRangeClick`/`toggleWordTarget`) نقي ومختبَر
منطقيًا (`tests/smart-create-multi-target.test.ts`)، واختبارات الاستكمال
في `tests/package06-wizard.test.ts`.

### 6.1 قاعدة من تحديد الحروف وتطبيقها في المصحف كله

من وضع التعليم بالحروف يمكن الضغط على **«حفظ كقاعدة في كل المصحف»** بدلا من إنشاء اختلاف موضعي. يفتح `GlobalRuleBuilder` ويحوّل المدى المحدد إلى نمط قابل لإعادة الفحص:

- الكلمة الأولى والثانية (وأي كلمات وسيطة) يجب أن تكون متجاورة داخل الآية؛ لا يعبر المحرك حد الآية.
- الحرف في أول/آخر الكلمة يثبت إلى الطرف (`START`/`END`) حتى تنطبق القاعدة على كلمات أطول أو أقصر، أما الحرف الداخلي فيبقى برقم موضعه.
- لكل حرف سياسة ضبط مستقلة: مطابقة العلامات نفسها (`EXACT`)، تجاهلها (`IGNORE`)، اشتراط السكون (`SAKIN` — يشمل علامة السكون بصورتيها الحديثة ْ والعثمانية ۡ والحرف المعرّى من الحركة كرسم النون قبل الإدغام والإخفاء)، أو اشتراط عدم وجود أي علامة (`NONE`).
- يمكن توسيع قيد الحرف إلى مجموعة حروف جاهزة، مثل **أي حرف من حروف الإخفاء**، بدلا من الحرف الذي استُخدم في المثال.
- **نطاق البحث** (`matchScope`): بين الكلمات كما حُدِّد (`WORDS`)، أو داخل الكلمة الواحدة (`INSIDE_WORD`) حيث يُبحث عن التتابع نفسه حروفا متجاورة في جوف كل كلمة («أَنتُمْ»، «يُنفِقُونَ»)، أو الاثنان معا (`BOTH`) وهو خيار الدقة الكاملة للأحكام الصوتية التي تجري بين الكلمتين وفي داخل الكلمة سواء.
- لا تُنسخ النتائج إلى 6236 مستندا؛ تحفظ القاعدة مرة واحدة في `global-rules-store` وتشتق منها اختلافات مؤقتة وقت الرسم، لذلك يظهر الخط في كل موضع مطابق دون تضخيم التخزين.

### 6.2 قاعدة حسب القواعد النحوية والصرفية

بدلا من تعيين الحروف بأعيانها، يستطيع المحقق وصف **صفة** الكلمة المستهدفة، مثل: «كل كلمة تنتهي بتاء التأنيث»، أو «كل ما جاء على وزن فُعْلَى». يجمع `GlobalRuleBuilder` بين محورين يعملان معا (AND):

| المحور | المعيار | أمثلة |
|--------|---------|-------|
| صرف | القالب الصرفي | `فَعْلَى` — `ف` و`ع` و`ل` خانات جذر، وسواها يطابق حرفيا |
| صرف | خصائص ظاهرة | تاء مربوطة، تاء مبسوطة، ألف مقصورة، ألف ممدودة، ياء نسب، تثنية، جمع سالم، تعريف بأل، تنوين، شدّة، همزة، حرف مد، **نون ساكنة في الآخر**، **ميم ساكنة في الآخر**، **واو الجماعة**، **همزة وصل في الأول**، **أل شمسية/قمرية**، **ضمير متصل** |
| صوت | أول/آخر حرف من مجموعة | أول الكلمة أو آخرها حرف من مجموعة تجويدية معلومة (إخفاء، إظهار، إدغام، إقلاب، قلقلة، غنة، مد) — همزة الوصل تُتخطى عند فحص أول الكلمة |
| صرف | خصائص مستثناة | ما يشبه المطلوب ولا يراد، مثل: على وزن `فُعْلَى` **بلا** أل |
| نحو | حركة آخر الكلمة | ضمة، فتحة، كسرة، سكون، وتنوين الثلاثة |
| نحو | الأداة السابقة أو اللاحقة | حرف جر، ناصب، جازم، إنّ وأخواتها، كان وأخواتها، نداء، استفهام، شرط، عطف، نفي، اسم موصول |
| نحو | موقع الكلمة من الآية | أولها، آخرها، غير آخرها |
| — | طول الكلمة | حدّ أدنى وحدّ أعلى بالحروف المرئية |

**سلاسل الكلمات:** القاعدة النحوية لم تعد مقصورة على كلمة واحدة؛ يمكن وصف حتى **4 كلمات متجاورة** لكل واحدة معاييرها المستقلة، فتُبنى قاعدة «كلمة تنتهي بنون ساكنة تليها كلمة أولها حرف إخفاء» بالمعايير لا بتعداد الحروف. وفي المنشئ قوالب جاهزة لأحكام النون الساكنة والتنوين الخمسة (إخفاء، إظهار، إدغام، إقلاب، إخفاء شفوي) والمد المنفصل.

**قيد منهجي صريح:** لا يحكم المحرك إلا بعلامة ظاهرة في الرسم أو الضبط، أو بأداة من **قائمة مغلقة معدودة** (`arabic-grammar.ts`). الإعراب المحتمِل والتحليل الدلالي خارج نطاقه عمدا؛ فقاعدة تخمّن أهون خطأً من قاعدة تُطبَّق على المصحف كله بلا دليل ظاهر.

### 6.2.1 الفهرس المدمج في المحرر

زر **«الفهرس»** أعلى لوحة الاختلافات يفتح `RulesIndexDialog` داخل المحرر نفسه: بحث وتصفية في كل القواعد العامة واختلافات الآيات (بالفئة والنوع والقارئ)، وتتبّع مواضع أي قاعدة، وتحريرها وإيقافها وحذفها، والانتقال إلى أي اختلاف موضعي في مكانه — كل ذلك دون مغادرة شاشة العمل. كما يمكن **تعميم** أي اختلاف حرفي قائم إلى قاعدة للمصحف كله بزر «تعميم على المصحف» في بطاقة الاختلاف وفي محرر الاختلاف، فتنتقل بياناته ونطاقه ودرجاته إلى منشئ القاعدة تلقائيا.

### 6.3 تتبّع مواضع القاعدة ومراجعتها

القاعدة الواحدة قد تصيب آلاف المواضع، والتطبيق الآلي ليس معصوما. لذلك يفتح زر **«تتبّع المواضع»** — من لوحة الاختلافات أو من صفحة الاختلافات العامة — مراجعةً موضعا موضعا بأزرار «التالي» و«السابق»، كتنقل الآيات نفسه:

- كل موضع يُعرض بنصه وآيته ومداه، مع رابط يفتحه في المحرر.
- **الحذف موضعي لا يتعدى صاحبه**: حذف القاعدة من «مَالِكِ» في الفاتحة لا يمسّها في غيرها.
- كل حذف أو إرجاع أو اعتماد أو تعديل درجة يُسجَّل في سجل ظاهر: أين ومتى ولماذا، فيبقى العمل قابلا للمراجعة والتراجع.
- لكل موضع درجة قوة خاصة إن خالف درجة القاعدة، فقد يتقدم الوجه في موضع ويتأخر في آخر.

**التخزين استثناءات فقط** (`rule-occurrences-store.ts`): الموضع الذي لم يُمسّ يبقى مشتقا من القاعدة بلا سطر ولا تكلفة، فلا تتضخم البيانات بـ 2344 نسخة من قاعدة واحدة.

### 6.4 درجة قوة الوجه لكل راوٍ

عند إنشاء القاعدة أو الوجه يُسأل المحقق عن **درجة القوة لكل راوٍ في النطاق على حدة**، لأن الرواة يختلفون في تقديم الوجه الواحد وتأخيره. ثم:

- رتبة الوجه في الترتيب = أصغر رتبة أعطاها له أحد رواته، والاختلاف يظهر في بطاقة الوجه لا يُهدَر.
- سلّم الدرجات نفسه قابل للتحرير من **الإعدادات ← سلّم درجات قوة الوجه**: أربع درجات افتراضية (مقدَّم، راجح، جائز، مؤخَّر) تُزاد إلى خمس أو أكثر، أو يُعاد ترتيبها وتُغيَّر ألوانها. ويمكن أيضا إضافة درجة جديدة **من داخل نموذج إنشاء القاعدة نفسه** بزر «+ درجة جديدة» في محدد الدرجات، فلا يقطع المحقق عمله للذهاب إلى الإعدادات.
- «الوجه المقدَّم» ليس مفهوما مستقلا، بل هو الدرجة المعلَّمة `isPreferred` في السلّم. التفصيل في `docs/TASHJEER_LOGIC.md`.

### التدقيق براو واحد

من لوحة الخصائص، اختر راويا واحدا في "تصفية الرواة". تظهر خطوطه وحدها، فيتحقق المدقق من قراءة هذا الراوي كاملة في الآية دفعة واحدة. هذه أقوى أداة تدقيق في المحرر.

## 6.5 سطر الراوي: أحكامه كلها في سطر واحد

المحرر لا يطلب من المحقق أن يجمع حكمين متباعدين بخط واحد ممتد. القاعدة:

1. **سجّل كل موضع اختلاف مستقلا** ولو كان في الآية نفسها: مدٌّ في الكلمة الأولى، وفرشٌ في الخامسة، وإدغامٌ في الثامنة — ثلاثة مواضع.
2. **المحرك يجمع.** كل من قرأ بهذه الأحكام الثلاثة يُرسم له **سطر واحد** فيه ثلاثة أحكام، كل حكم مغلَّظ فوق كلمته ومكتوب اسمه ومقدار مدّه بالأرقام العربية.
3. **تعدد الأوجه يولّد سطورا بالضرب.** وجهان في موضع وثلاثة في آخر = ستة سطور للراوي، مرتبة: المقدَّم أولا.
4. **النقر على حكم** داخل السطر يفتح موضعه هو، لا أول مواضع السطر.

يمكن العودة إلى العرض الموضعي (سطر لكل وجه) من زر **«أوجه مركّبة / سطر لكل وجه»** في شريط الأدوات، أو من لوحة التحكم.

## 6.6 نافذة العمل: وصل الآيتين وتشجير مقطع

في لوحة «الوقف والابتداء»:

- **ضمّ الآية التالية** إلى نافذة العمل، فتتسلسل مواضع الكلمات عبر الآيتين ويمكن تسجيل حكم بينهما. يظهر رقم الآية الأولى في موضعه بين النصين.
- **تشجير مقطع وحده**: تختار مقطعا من مقاطع الوقف، أو «ما قبل الكلمة المحددة»، فيقتصر التشجير عليه ويُخفَّت ما عداه.

الاختياران محفوظان في المستند (`readingWindow`)، فينتقلان مع التصدير.

## 6.7 المحرر يصحّح المحرك: الروابط والأجزاء والترتيب (v7)

هذه هي مرحلة «التحكم اليدوي» في نتيجة المحرك. المحرك يقترح، والمحرر يصحّح،
والتصحيح يُحفظ **كبيانات صريحة** في المستند لا كمظهر عابر، فيدخل ملف JSON
ويظهر في التتبع وينعكس على صفحة المصحف.

البنية الموحدة تربط سلسلة العمل كلها:

```
الآية → السطر → الجزء → القاعدة → الترتيب → العلاقة → الوجه المركب
```

| النوع | المعنى | أثر MERGE | أثر REFERENCE |
|-------|--------|-----------|----------------|
| `FACE_TO_FACE` | هذا الوجه مرتبط/متفق مع وجه آخر | سطر واحد يحمل الوجهين | وسم العلاقة دون تغيير الأسطر |
| `LINE_TO_LINE` | دمج سطر بسطر في تركيب واحد | سطر واحد بأحكام السطرين | وسم العلاقة |
| `SEGMENT_TO_LINE` | جزء من الآية يتبع سطرا آخر | الجزء يُلحق بأحكام السطر الهدف | وسم العلاقة |
| `SEGMENT_TO_RULE` | جزء يرتبط بقاعدة في سطر آخر | الجزء يُلحق بأول سطر يحمل القاعدة | وسم العلاقة |
| `DIFFERENCE_TO_DIFFERENCE` | تصنيف يدوي موثق لعلاقة اختلافين في موضع واحد (متنافيان/مرتبطان — الحزمة 05) | — | قرار يسبق السياسة في محرك التراكيب (انظر §6.9) |

لا تفترض الروابط شيئا عن القارئ: الوجهان المرتبطان قد يكونان من راويين
مختلفين، لأن قرار المحقق هو مصدر الحقيقة لا افتراض المحرك.

الإنشاء والتعديل والحذف من **لوحة «العلاقات والتحكم اليدوي»** في لوحة
الخصائص (أربع تبويبات: وجه↔وجه، سطر↔سطر، جزء→قاعدة، ترتيب الأسطر)، وكل
علاقة تظهر بحالتها: مفعّلة (طرفها ظاهر) أو معلّقة (طرفها خارج العرض الحالي
بسبب تصفية أو حذف).

### الأجزاء (LineSegment) — نموذج Line→Segment→Rule

الجزء مدى كلمات أو حروف داخل الآية يُعزل بعنوانه الخاص ثم يُربط بسطر أو
قاعدة في سطر آخر. هكذا يغطي السطر القائم كلمات موزعة **دون إنشاء سطر جديد
كامل** يحمل القاعدة نفسها، وهو الأساس الذي ستُبنى عليه خوارزميات ترتيب
أدق مستقبلا.

الإنشاء: علّم الكلمات (أو الحروف) في اللوحة، ثم اكتب عنوان الجزء في تبويب
«جزء → قاعدة» واختر هدفه.

### الترتيب اليدوي (lineOrder)

تبويب «ترتيب الأسطر» يعرض أسطر المحرك بأرقامها الحالية. تغيير رقم سطر أو
النقل بالسهمين يثبّت ترتيبا يدويا كاملا بإزاحة إدراج: الصفوف المتأثرة
تتحرك رتبة واحدة، فلا يتعطل الترتيب ولا تتلف العلاقات المرتبطة بالأسطر.
زر «عودة لترتيب المحرك» يحرر الترتيب اليدوي كله.

### رقم ترتيب السطر للقواعد العامة (orderRank)

- عند إنشاء قاعدة عامة من المحرر: حقل «رقم ترتيب السطر» في منشئ القاعدة.
- بعدها: من «تحرير القاعدة العامة» في فهرس القواعد، مع إلغاء الترتيب.
- لكل موضع بعينه: من شاشة تتبّع مواضع القاعدة (تخصيص يسبق رتبة القاعدة).
- تثبيت رتبة قاعدة يزيح المتأثرين تلقائيا (`setGlobalRuleOrderRank`).

### سجل التعديل (editLog) والتتبع

كل عملية يدوية على الاختلافات والأوجه والروابط والأجزاء والترتيب تُسجَّل في
`document.editLog` بقيمة الحقول **قبل وبعد** وبمصدر التعديل (`EDITOR`).
صفحة **`/tracking`** تقرأ السجل مع المستندات وتصنّف المواضع حسب الفئة
(المدود، الفرش، الأصول، التجويد...) والمصدر:

- ماذا وجد المحرك (قواعد عامة مشتقة وبيانات أساسية).
- ماذا أضاف المحرر (origin: EDITOR).
- ماذا عُدّل يدويا، مع فروق «قبل ← بعد» لكل تصحيح.
- انتقال مباشر من كل صف إلى موضعه في المحرر.

هذه الملفات المصحّحة هي **البيانات المرجعية** لتحليل أخطاء المحرك وتطوير
خوارزمياته: المحرر أداة تدريب للمحرك لا مجرد واجهة تعديل.

### انعكاس فوري في /quran

صفحة المصحف ترسم لكل آية محفوظة بطاقة تشجيرها النهائي **بنفس خط الأنابيب**
الذي يرسم المحرر (نفس المستند، المحرك، الروابط، والترتيب اليدوي)، فيتطابق
النتيجتان: المحرر → حفظ → /quran.

## 6.8 الاستقلال المحلي بعد التعميم (FR-ED-10 · PH6)

الإنشاء الجماعي لا يربط التحرير بين الأنواع. المعالج ينشئ قواعد مستقلة ذات
`createBatchId` مشترك للتتبع فقط. **تحقيق (`TAHQIQ`)=١، أصول (`USUL`)=٢، فرش
(`FARSH`)=٣** هي رتب الإنشاء الافتراضية الرقمية في `type-ranks.ts`، لا فرز
بالاسم ولا بترتيب النقر. لا تُعاد كتابة رتب البيانات القديمة عند القراءة؛
الرتبة المحفوظة، ثم تجاوزها المحلي، هي الحاكمة. وضع الدفعة `rankMode: TYPE`
لا يزيح رتب قواعد أُنشئت سابقًا. تغيير الاسم أو إعدادات العرض لا يغير الرتبة.

لوحة **«ترتيب التشجير في هذه الآية»** تعرض كل موضع مستقلًا. والرسم المشترك
للمحرر و`/quran` يعرض مصدر كل حكم: **قاعدة عامة / يدوي / محرك**، مع شارة
**«متجاوز محليًا»** عند تخصيص قيمه. الأنواع المتراكبة على الكلمة نفسها تأخذ
مستويات فرعية مرتبة حتى لا تتطابق نصوصها فوق بعضها.

### بروتوكول التجاوزات

- **تحرير محلي**: العنوان، النوع، النص، الحكم، الوصف، المصدر، مقدار المد،
  التسمية، الملاحظات، نطاق القراء، الرتبة ودرجة القوة (العامة ولكل راوٍ).
  الحفظ معاملة واحدة في طبقة الموضع؛ لا يضيف المشتق إلى `document.variants`.
  ويصل التحرير عبر إجراءات الوجه المعتادة إلى الطبقة نفسها.
- الحقل غير المذكور يبقى كما هو. تحرير الحقل بـ`undefined` يعيده إلى
  **اتباع الأمّ**، وليس إلى قيمة فارغة. النموذج يعرض الحقول النصية المخصصة
  فقط؛ تركها فارغة يلغي تخصيصها. عند تعديل الأمّ يغلب **الحقل المتجاوز**،
  وتستمر الحقول الأخرى في التوريث (التجاوز ليس تجميدًا لكل القاعدة).
- **حذف موضعي** بتأكيد: يسجل `state: DELETED` ويحفظ الترقيع السابق، دون حذف
  الأمّ أو الأشقاء. زر **إرجاع** يعيد الموضع بتخصيصاته، مع Undo/Redo.
- **إلغاء التجاوز**: يمحو تخصيص القيم والرتبة والقوة وموضع النقل؛ يتبع الموضع
  أمّه من جديد. الحالة مستقلة: المحذوف يُعاد بزر «إرجاع»، والمعتمد يظل معتمدًا.
- **النسخ/النقل** يستخدمان حافظة الحزمة ٠٤، لا مسار نسخ موازٍ:
  - حدد النوع ثم «نسخ»/Ctrl+C أو «نقل»/Ctrl+X. المصدر لا يتغير قبل اللصق.
  - حدد **كلمة** في الآية نفسها أو في آية أخرى ثم Ctrl+V: الوجهة مدى كلمات
    يبدأ بالكلمة المحددة وبطول مدى المصدر. النسخ ينشئ كيانًا يدويًا بمعرّفات
    جديدة و`copiedFrom`؛ النقل يخزن `patch.placement` فقط **بنفس معرّف الموضع**،
    ولا يكتب نسخة إلى مستند المصدر أو الوجهة. مرساة المطابقة الأصلية ثابتة.
  - أو حدد **سطرًا** داخل الآية والصق: رابط `DIFFERENCE_TO_LINE` ينقل أحكام
    هذا النوع وحده، لا بقية الأحكام الموجودة على سطره. النسخ يُرسي النسخة
    على السطر، والنقل يُرسي الأصل بلا استنساخ.
  - القص القديم بعد تعديل المصدر أو الوجهة غير الصالحة يُرفضان بلا حذف.
    روابط الآية المصدر مع عناصر خارج النقل لا تُطبق تلقائيًا في آية أخرى؛
    تبقى محفوظة في المصدر (تصير غير فاعلة ما دام الطرف منقولًا).
- **علاقة/ربط بوجه آخر** من خصائص النوع أو لوحة العلاقات: روابط محلية
  بمعرّفات الموضع/الوجه، لا بمعرّف القاعدة الأم. تمر عبر Resolver وتأكيد.
  **دمج نوع مشتق** يحوّل الرابط إلى رسوّ ذلك النوع وحده على وجه الهدف، فلا
  يجرّ الأشقاء معه. مخالفة اقتراح الدمج تُحذّر ثم تُوثق بـCorrection.
  **الفصل** من لوحة العلاقات بتحويل الدمج إلى مرجع أو حذف الرابط بتأكيد؛
  البيانات الأصلية لم تُستبدل أصلًا. دمج السطر الكامل وفكه يبقيان عمليتين
  منفصلتين ذواتي لقطات `mergeRecords` كما في الحزمة ٠٤.

**الأمّ محمية:** تعديلها يعرض عدد المواضع ونطاق الحماية المحلية؛ حذفها يعرض
العدد الكامل للمطابقات **بلا سقف ٥٠٠٠** والاستثناءات والتجاوزات قبل التنفيذ.
حذف الأمّ يزيل مشتقاتها، بما فيها المنقولة، وUndo يعيد القواعد والاستثناءات
والسجل معًا. لا تُنشأ آلاف مستندات الآيات؛ النقل نفسه استثناء صغير.

**التتبع والتراجع:** تعديلات القيم تسجل في `occurrenceLog` قبل/بعد مع
`source: editor`، وفي سجل المحرر بهدف `RULE`. العلاقات والنسخ والفصل تسجل
قبل/بعد في سجل المستند بمصدر المحرر. التراجع موحد للمستند ومخزني القواعد
والمواضع، ويشمل النقل عبر الآيات من جلسة الوجهة. `/quran` يقرأ الطبقة نفسها
ويكتشف حتى المواضع المنقولة إلى آيات لا تطابق النمط، بلا حفظ مستند لها.

## 6.9 تعدد الاختلافات للموضع الواحد (FR-ED-03 · DM-09)

القاعدة الصارمة: **الاختلافات المتعددة لنفس الكلمة لا تُدمج تلقائيًا لمجرد
أنها لنفس القارئ**. القارئ X قد يكون له في الكلمة Y أربعة اختلافات حية:
مدٌّ، ومدٌّ آخر، وصلة، وفرش — كل واحد كيان مستقل بمعرّفه ونوعه ومصدره
(محرك/محرر) ورتبته وعلاقاته، وحذف أحدها أو تعديله لا يمس البقية.

**الإنشاء بلا استبدال**: إضافة «اختلاف ثانٍ لنفس القارئ والكلمة» متاحة
ومباشرة من باب الإنشاء القائم (المعالج الذكي N أو الإنشاء السريع)؛ المعالج
يعرض في خطوة التحديد الاختلافات القائمة في الموضع ويوضح أن الإنشاء يضيف
كيانًا مستقلًا جديدًا ولا يستبدلها. عند تحقق التعدد تظهر رسالة حالة أعلى
قائمة الاختلافات: **«اختلافان لموضع واحد — أُضيف ... اختلافًا ثانيًا مستقلًا
بمعرّفه، والأول ... كما هو بلا تغيير»** (وبالجمع: «٣ اختلافات لموضع واحد»).

**لوحة التفاصيل**: عند تحديد كلمة (أو حكم في سطر) تعرض لوحة «العنصر المحدد»
قسم **«اختلافات الموضع»** بكل اختلافات الكلمة مرتبة ترتيبًا حتميًا:
المصدر (محرك ثم محرر)، ثم الرتبة الصريحة، ثم فهرس التعدد (اختلاف ١، ٢، ٣…).
كل صف قابل للتحديد المستقل (التحديد الموحد من الحزمة 03) ويعرض شارات:
- **الفهرس** — «اختلاف ١/٢/٣…» داخل مجموعة التعدد (الموضع + نطاق القرّاء).
- **النوع** — مد/صلة/فرش/تحقيق… بلون الفئة.
- **المصدر** — محرك أو محرر.
- **الحالة** — **متنافٍ** (لا يُضرب مع غيره: مد ٢ ومد ٤ وجهان لموضع واحد)،
  **مرتبط** (يجتمع مع غيره في السطر: مد مع تحقيق)، أو **مستقل** (بُعد قائم
  بذاته: مد مع فرش). القرار من Decision Resolver عبر سياسات الاستوديو
  حصرًا — لا منطق عرض خاص في اللوحات (P-07).

**تصحيح علاقة التنافي يدويًا (المحرك يقترح والمحرر يقرر)**: تحت كل صف (غير
المحدد) زران «متنافيان / مرتبطان» يسجلان علاقة يدوية موثقة بينه وبين الاختلاف
المحدد. التسجيل يمر بتأكيد كمي؛ فإن خالف قرار المحرر اقتراح السياسة (مثل
تسجيل «مرتبطان» لمدّين تراهما السياسة متنافيين) حُفظ معه **Correction**
موثقة (اقتراح المحرك A / قرار المحرر B / النهائي = B — DM-05)، وسبقَت
العلاقة اليدوية السياسة في محرك التراكيب من يوم تسجيلها. العلاقات اليدوية
تظهر أيضًا في لوحة «العلاقات والتحكم اليدوي» (اختلاف ↔ اختلاف) مع زر قلب
التصنيف، وتُصدَّر إلى v8 بنوعها الصريح (`MUTUALLY_EXCLUSIVE`/`RELATED`).

**في محرك التراكيب والرسم** (تعميم السلوك القائم): المتنافيان لا يُضربان —
يظهران وجهين لموضع واحد (سطر لكل وجه)، والمستقلان يُطبقان معًا في سطر الراوي
كلٌّ فوق كلمته بعلامته. في المثال المرجعي (مد، مد آخر، صلة، فرش لقالون في
كلمة واحدة): سطران لقالون — (المد الأول × صلة × فرش) و(المد الثاني × صلة ×
فرش) — والأحكام الأربعة كلها حية فوق كلمتها.

الفهرسة والترتيب والرسالة تحسبها الدوال النقية في
`lib/tashjeer/difference-occurrences.ts` — المكان الواحد الذي يستعمله المحرر
والترحيل v7→v8 والاختبارات معًا، فلا يختلف العرض عن التصدير.

## 7.1 الحافظة المتعددة والتحديد المتعدد (FR-ED-06/07)

خدمة `lib/tashjeer/clipboard.ts` واحدة، وتحديد متعدد في مخزن المحرر (`multiSelection`) في **كل قوائم العناصر**: الاختلافات المحفوظة، الأوجه داخل اختلاف، الأسطر في لوحة الترتيب، القواعد العامة في الفهرس، ومواضع القاعدة في شاشة التتبّع (`kind` واحدة: `DIFFERENCE | FACE | LINE | RULE | OCCURRENCE` وخوارزمية `selectRange` واحدة). النقر المفرد يستبدل التحديد، Ctrl يبدّل العنصر، Shift يحدد المدى، وCtrl+A يحدد القائمة المصفّاة، لا المصحف كله. لا تُحذف عناصر أخفاها البحث أو المرشّح.

- **مستويات الحافظة:** سطر كامل (اختلافاته **وأجزاؤه**) · جزء من سطر (اختلافات محدّدة) · اختلاف واحد · وجه/أوجه · **قاعدة عامة**. النسخ لقطة مستقلة بمعرّفات جديدة للأجزاء والاختلافات والأوجه والأدلة والقواعد، و`copiedFrom` يوثّق الأصل، و`createdAt/updatedAt` جديدة و`source: editor`، وترتيب الأوجه الداخلي يُعاد ربطه بالمعرّفات الجديدة. نسخ القواعد يُولّد `createBatchId` مشتركًا للدفعة ليعرف التراجع أنها وحدة (DM-08)، ويضبط حالتها «مسودة» لأن التوثيق لا يُورَّث.
- **القص:** لا يغيّر المستند ولا يستهلك خطوة Undo. نقل الأوجه داخل المستند يعمل بعد اختيار اختلاف آخر والتأكيد؛ يحتفظ بمعرّفاتها ويعيد توجيه روابطها. الوجهة غير الصالحة أو المصدر المعدّل بعد القص يُرفضان دون حذف المصدر. النقل بين مستندين غير متاح بعد. قص **قاعدة عامة** ينقلها: تُنشأ النسخة بمعرّف جديد ثم تُحذف القاعدة الأم ومخزن مواضعها في المعاملة نفسها، وخطوة تراجع واحدة تعيد الاثنين.
- **اللصق:** `requestPasteSelection` يطلب التأكيد دائمًا مع العدد والوجهة؛ يُلحِق الأوجه في نهاية الوجهة ولا يبدّل بقية عناصرها. `pasteSelection` أمر منخفض المستوى متزامن لا تستدعيه واجهة المستخدم مباشرة.
- **اللصق/النقل داخل سطر هدف (AC-04):** عندما يكون المحدد في التحديد الموحّد **سطرًا** (`LINE` باختلاف مرسى)، تُلحَق الاختلافات الملصوقة بذلك السطر بدل رميها في المستند، عبر رابط بنائي جديد `DIFFERENCE_TO_LINE` (من = اختلاف، إلى = **وجه** داخل السطر → الرسو بمعرّف وجه مستقر لا بمعرّف السطر المرئي المتغير). النسخة (C) تستنسخ بمعرّفات جديدة ثم ترسو، والنقل (X) يرسو بالأصل بلا استنساخ ولا حذف — معرّفاته وعلاقاته محفوظة. عند العرض (`applyManualLinks` ← `moveDifferenceIntoLine`) تُنقل أحكام الاختلاف وحدها من أسطرها الطبيعية إلى سطر المرساة (لا يُسحب السطر كله كما في دمج LINE_TO_LINE)، ويُسقط السطر المفرَّغ، وتُلحق الأحكام في **نهاية** أحكام الهدف. حذف الرابط من لوحة العلاقات يُعيد الاختلاف إلى سطره الطبيعي (فك الإلحاق). بلا سطر محدد يبقى اللصق بسلوك المستند، والقص يُرفض برسالة إرشاد دون مساس بالمصدر.
- **العلاقات:** العلاقات الداخلية تُنسخ بطرفين جديدين. العلاقة التي يغيب أحد طرفيها عن مجموعة النسخ لا تُفعّل؛ تُحفظ في `suspendedLinks` ويعرضها قسم «الحافظة» في الشريط للمراجعة، مع أصلها والطرف المعاد تعيينه. الإجراء التفاعلي لإعادة ربط هذه العلاقات مؤجل.
- **الحذف الجماعي:** شريط إجراءات جماعية في رأس كل قائمة (`role="toolbar"`) متى وُجد تحديد متعدد، وفيه «حذف المحدد» و«نسخ» و«تفريغ» — إلغاء التأكيد يُبقي التحديد والبيانات، والتأكيد خطوة Undo واحدة:
  - **الاختلافات** (قائمة الاختلافات): العدد والعلاقات المتأثرة، والمحذوفات وروابطها إلى `deletedItems`. هذه الأرشفة لا تحذف القاعدة الأم.
  - **الأوجه**: بخانات التحديد داخل كل اختلاف (`deleteAlternativesBulk`).
  - **الأسطر** (لوحة الترتيب): يُحذف **الحصري** وحده — الاختلاف الذي يعرضه سطر باقٍ يُبلَّغ عنه في الحوار ويبقى (`exclusiveLineDifferences`)، فلا يُحذف بسطرٍ قراءةٌ يشترك فيها سطر آخر. موقوف أثناء التصفية لأن الأسطر المخفية ليست في الرسم المحسوب.
  - **القواعد العامة** (الفهرس): حوار كمي بعدد المواضع المشتقة في المصحف والاستثناءات المسجّلة والمحذوفة موضعيًا — وهذا هو «حذف القاعدة الأم» الصريح؛ التراجع يعيد القواعد واستثناءاتها معًا لأن اللقطة الموحّدة تلتقط المخزنين.
  - **مواضع القاعدة** (شاشة التتبّع): قائمة مواضع قابلة للتحديد فوق بطاقة الاستعراض، وحذفها الجماعي **تجاوز محلي (localOverride) لكل موضع** مع سبب يُسجَّل في سجل التغييرات؛ القاعدة الأم باقية وبقية مواضعها لا تُمس.

**حدود حزمة ٠٤:** نسخ/نقل الاختلافات داخل سطر هدف (AC-04) مُنفَّذ بالرابط البنائي أعلاه، ونسخ السطر الكامل يشمل أجزاؤه (`copyLine` يمرّر معرّفات الأجزاء التي تحملها أحكام السطر، فتُستنسخ بمعرّفات جديدة و`copiedFrom`، وتتبعها روابطها أو تُعلَّق dangling إن أشارت إلى خارج مجموعة النسخ). أسطر المحرر مشتقة من الاختلافات في نموذج التوافق؛ ليس لكل اختلاف ملكية داخل Line مستقل — وهو سبب اختيار الرابط البنائي وسيلةَ الإلحاق لا إعادة الملكية، وسبب كون «حذف الأسطر» حذفًا لاختلافاتها الحصرية لا لكيان السطر نفسه.

## 7.2 التأكيد الكمي للعمليات المدمّرة (FR-ED-04.2، NFR-05)

مداخل المستخدم الجديدة للحذف الجماعي واللصق ونقل/دمج/فك الأسطر تمرّ بـ `confirmAction({ title, message,
impacts: [{ label, count }], undoable, tone })` من `lib/ui/confirm-store.ts`،
ويعرضه `ConfirmDialogHost` المركّب في تخطيط لوحة التحكم. الحوار يبيّن الأثر
بالأرقام (عدد الأوجه، الروابط اليدوية، المواضع في المصحف، القواعد المعتمِدة...)
وهل العملية قابلة للتراجع. التركيز يبدأ على «إلغاء»، وEnter ينفّذ الزر المركّز لا التأكيد التلقائي؛ Tab محصور في الحوار وEsc يلغي. تتعطل اختصارات المستند أثناء الحوار. إذا تغيّر المستند أو وجهة اللصق أثناء انتظاره، يُلغى تطبيق الطلب القديم.

## 7.3 إحضار المحدَّد ونبضه (FR-ED-02.4)

## 7.4 السحب وإعادة الترتيب والدمج (FR-ED-04/05)

افتح `/editor` ← لوحة الخصائص ← **العلاقات والتحكم اليدوي ← ترتيب الأسطر**:

1. اضغط على جسم السطر ٣٥٠ مللي ثانية بالفأرة أو اللمس/القلم؛ لا يبدأ السحب من نقرة عادية. يتحول السطر إلى تمييز أخضر.
2. تحرّك رأسيًا إلى الفاصل المطلوب؛ يظهر خط إدراج أخضر مضيء، بما في ذلك بعد آخر سطر. يمكن تمرير القائمة نحو الحافة أثناء السحب.
3. ارفع المؤشر: تظهر رسالة برقم السطر والجيران والرتبة النهائية وعدد الأسطر المتأثرة. **لا نقل قبل التأكيد**، ولا خيار لتعطيله. Esc أو `pointercancel` أو الإفلات خارج القائمة يلغي الإيماءة.
4. التأكيد يحرّك السطر بالإدراج، لا بالتبديل. `Line.order` صريح، مع `lineOrder` للتوافق مع الرسم القديم. يبقى معرّف السطر ومعرّفات أجزائه وروابطه ثابتة؛ تتغيّر رتب المتأثرين فقط، وتُسجّل قيم قبل/بعد بمصدر المحرر. الحفظ/التصدير يحتفظان بالبيانات الجديدة.
5. البدائل: حقل الرتبة بالأرقام العربية، أزرار ↑/↓، أو `Alt+↑/↓` عند تركيز الصف؛ كلها تطلب التأكيد. النقل أثناء تصفية الأسطر موقوف برسالة أمان حتى لا يُستبدل ترتيب الأسطر المخفية.

السحب يستعمل Pointer Events والتقاط المؤشر للفأرة واللمس معًا، بلا HTML5 Drag & Drop وبلا تحريك اللوحة عرضيًا. السحب في **لوحة الترتيب** فقط؛ `/quran` يبقى عرضًا نهائيًا بلا مقابض تحرير.

**الدمج:** اضغط مطولًا على ↳ ثم أسقطه على سطر آخر. `resolveLineMerge` يترجم فئات أجزاء السطر إلى Decision API (`resolveMerge` وقرار العلاقة)، ولا تحسم الواجهة السياسة. الحوار يعرض الأسطر والأجزاء والأوجه الفريدة. عند المنع يعرض السبب والقاعدة والأولوية، ولا ينفّذ إلا بخيار **«تجاوز بقرار يدوي موثق»** الذي ينشئ Correction بسبب التجاوز. الدمج يحتفظ بمعرّف السطر الأول ويسجل الأصلين في علاقة MERGE و`mergeRecords`؛ لا يعيد توليد معرّفات الكيانات.

**الفك:** «فك الدمج» من قائمة العلاقات، بتأكيد. يعيد اللقطتين الأصليتين إذا كانت لقطة ما بعد الدمج لا تزال مطابقة. إذا تغيرت أو دخلت في دمج لاحق، يعرض سبب الرفض بدل إتلاف التعديلات؛ تراجع عن العمليات اللاحقة أولًا. الدمج والفك خطوتان مستقلتان قابلتان للتراجع.

**سجل العمليات:** في الشريط قائمة قابلة للفتح تتضمن الحالات السابقة والحالية والقابلة للإعادة؛ اختيار حالة يطلب تأكيد عدد العمليات ثم يستعمل `past/future` القائمين. لا يوجد سجل منافس جديد. يبقى حد الجلسة القائم ٦٠ لقطة لكل مستند. تغطي أيضًا تعديلات القواعد وlocalOverride المنفَّذة عبر `transactExternal`، لأن لقطة التراجع تضم المخزنين مع المستند.

## 7.5 تفضيلات مساحة العمل والقوائم الطويلة (FR-ED-01، NFR-01)

إظهار اللوحات وخيارات العرض (البطاقات/الشبكة/المساطر/المراسي) تُحفظ في
`tashjeer:editor-workspace:v1` وتُستعاد عند الفتح؛ لا تدخل في التصدير. قائمة
الاختلافات تُنافَذ (`useWindowedList`) عندما تتجاوز ٤٠ موضعًا: يُرسم المرئي مع
هامش، والصف المحدد يُرسم دائمًا.
