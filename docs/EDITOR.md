# توثيق المحرر - Editor Documentation

> المرجع الكامل لمحرر التشجير: نموذج البيانات، محركات الحساب، المكونات، وطريقة العمل.

---

## 1. لماذا أُعيد بناء المحرر؟

المحرر في النسخة الأولى كان يرسم خطوطا حرة مرتبطة بـ `qiraahId` رقمي. هذا التصميم فيه ثلاث مشكلات منهجية:

| المشكلة | الأثر |
|---------|-------|
| الخط مرتبط براو واحد | الحكم الذي يقرأ به 19 راويا يحتاج 19 خطا مكررا |
| الرسم يدوي بالكامل | المحرر يرسم شكلا، ولا يسجّل معلومة قابلة للتحقق |
| لا وجود للدليل ولا للنطاق | لا يمكن مراجعة العمل علميا |

النسخة الحالية تقلب المعادلة: **المستخدم يسجّل الاختلاف، والمحرك يرسم الخطوط.**

## 2. نموذج البيانات

الملف: `src/types/tashjeer.ts`

```
TashjeerDocument (مستند آية واحدة)
├── variants: Variant[]           ← الاختلافات المسجّلة
│   └── alternatives: VariantAlternative[]   ← أوجه الاختلاف
│       ├── scope: ReadingScope   ← من يقرأ بهذا الوجه
│       └── evidences: VariantEvidence[]     ← الأدلة
├── branches: TashjeerBranch[]    ← الخطوط (مولّدة تلقائيا)
└── meta: DocumentMeta            ← التوثيق وحالة المراجعة
```

### 2.1 الاختلاف (Variant)

موضع في الآية تختلف فيه القراءة. له:

- **فئة** (`category`): أصول، فرش، مدود، همز، وقف، تجويد.
- **مدى كلمات** (`startPosition` .. `endPosition`) بترقيم 1-based داخل الآية.
- **أوجه** (`alternatives`): وجه واحد منها هو `isBase` أي نص المصحف المطبوع.
- **حالة** (`status`): مسودة، قيد المراجعة، معتمد، مرفوض.

### 2.2 الوجه (VariantAlternative)

نص معيّن يقرأ به نطاق معيّن. الوجه المعلَّم بـ `isBase: true` **لا يُرسم له خط**، لأنه هو النص المكتوب على اللوحة أصلا (رواية حفص).

### 2.3 النطاق (ReadingScope)

هذا هو حل مشكلة التكرار. بدل تخزين الحكم لكل راو، نخزّنه مرة واحدة مع تعبير عن مجموعة القرّاء:

| النوع | المعنى | مثال |
|-------|--------|------|
| `ALL` | الرواة العشرون | حكم متفق عليه |
| `ALL_EXCEPT` | الجميع إلا المذكورين | `عليهم` بالكسر: الجميع إلا حمزة ويعقوب |
| `IMAMS` | كل رواة أئمة معيّنين | `عاصم` = حفص وشعبة |
| `NARRATORS` | قائمة رواة صريحة | ورش والسوسي وابن وردان |
| `PATHS` | طرق محددة | طريق الأزرق عن ورش |

الملف: `src/lib/tashjeer/scope.ts`

**دالة `normalizeScope`** تختصر أي قائمة رواة إلى أبسط تعبير تلقائيا:

```ts
normalizeScope(['narrator-hafs', 'narrator-shubah'])
// → { kind: 'IMAMS', imamIds: ['imam-asim'] }

normalizeScope(كل الرواة عدا حفص)
// → { kind: 'ALL_EXCEPT', narratorIds: ['narrator-hafs'] }
```

**دالة `describeScope`** تبني وصفا عربيا للعرض على بطاقة الوجه:

```ts
describeScope({ kind: 'IMAMS', imamIds: ['imam-asim'] })  // "عاصم بكماله"
describeScope({ kind: 'ALL_EXCEPT', narratorIds: [حفص] }) // "الجميع إلا حفص"
```

## 3. المحركات

### 3.1 محرك التخطيط (`layout-engine.ts`)

يحوّل كلمات الآية إلى صناديق (`WordBox`) لها إحداثيات دقيقة.

**لماذا لا نقيس بالمتصفح؟** لأن المحرر يجب أن يعطي نفس الناتج على الخادم (SSR) وفي الاختبارات. فالقياس بنموذج رياضي حتمي:

```ts
measureWordWidth('ٱلرَّحِيمِ', 34)  // نفس القيمة دائما
```

**قواعد القياس:**

- كل حرف له معامل عرض نسبي لحجم الخط (`LETTER_WIDTH_RATIO`).
- الحركات والتنوين والسكون والشدة وعلامات الوقف **عرضها صفر**، لأنها تُرسم فوق الحرف أو تحته.
- الألف الخنجرية (`U+0670`) عرضها صفر كذلك: `مَٰلِكِ` أضيق من `مَالِكِ`.
- الاتجاه من اليمين لليسار: نبدأ من `canvasWidth - paddingRight` ونتقدم يسارا.
- الالتفاف تلقائي عند بلوغ الهامش الأيسر.

كل صندوق يعطي ثلاث نقاط ارتباط: `topY` (للأصول) و`bottomY` (للفرش) و`centerX`.

### 3.2 محرك التشجير (`branch-engine.ts`)

قلب المشروع. يحوّل الاختلافات إلى خطوط مرسومة، وفق أربع قواعد منهجية:

#### القاعدة 1: وجه المصحف لا يُرسم

```ts
if (alternative.isBase) continue;
```

#### القاعدة 2: توزيع المناطق

| الجهة | الفئات | السبب |
|-------|--------|-------|
| فوق النص | أصول، مدود | أحكام عامة مطّردة في نظائرها |
| تحت النص | فرش، همز، وقف، تجويد | مواضع جزئية مرتبطة بكلمة بعينها |

#### القاعدة 3: الترتيب من آخر الآية إلى أولها

القاعدة المعتمدة في المشروع: يُقرأ الاختلاف من آخر الآية إلى أولها. لذلك الخط الذي تبدأ عقدته في موضع **متأخر** يأخذ مسارا **أقرب إلى النص**:

```ts
if (aStart !== bStart) return bStart - aStart;  // الأكبر موضعا أولا
```

#### القاعدة 4: تعبئة المسارات (Lane Packing)

خطان لا يتقاطعان أفقيا يتشاركان نفس المسار. هذه خوارزمية تلوين مخطط فترات (interval-graph coloring) مبسطة، تقلّل ارتفاع اللوحة كثيرا في الآيات المزدحمة:

```
اختلاف في الكلمة 1  ──────┐
                          ├─ نفس المسار (لا تداخل)
اختلاف في الكلمة 8  ──────┘

اختلاف 1..5  ─────┐
                  ├─ مساران منفصلان (متداخلان)
اختلاف 3..7  ─────┘
```

#### الشكل الهندسي للخط

من نقطة الارتباط بالكلمة، منحنى تربيعي قصير إلى المسار الأفقي، ثم سير على المسار، ثم بطاقة الوجه في الطرف الأيسر. الكلمات الوسيطة تُربط بخطوط عمودية قصيرة.

### لماذا SVG وليس Canvas؟

- النص العربي يُرسم بخط المصحف مع تشكيله دون معالجة يدوية للحروف.
- كل عنصر قابل للتحديد والاختبار والتصدير.
- التكبير متجهي لا يفقد الدقة.

### محدد النطاق (ScopePicker)

أهم عنصر في `VariantEditor`. يعرض القراء العشرة، وتحت كل واحد راوييه. النقر على اسم الإمام يختار رواته كلهم. لون كل إمام ثابت، فرواة الإمام الواحد يشتركون في اللون.

بعد كل تغيير يُستدعى `normalizeScope` تلقائيا، فلا يخزَّن "حفص + شعبة" بل "عاصم".

## 5. الحالة والتخزين

### 5.1 مخزن المحرر (`stores/editor-store.ts`)

**مبدأ التراجع:** يعمل على المستند نفسه لا على حالة الواجهة.

- تعديل حقيقي (إضافة اختلاف، حذف وجه) → تُسجَّل لقطة كاملة للمستند.
- تغيير عرض (تكبير، فتح لوحة) → **لا** تُسجَّل لقطة.

السبب: المستخدم لا يتوقع أن يتراجع `Ctrl+Z` عن تكبير الشاشة.

**إعادة التوليد:** بعد أي تعديل على الاختلافات، تُعاد الخطوط تلقائيا عبر `generateBranches`، مع الحفاظ على الخطوط المعلَّمة `isManual`.

### 5.2 مخزن المستندات (`lib/storage/document-store.ts`)

التخزين محلي في `localStorage` بقرار من صاحب المشروع، حتى يستقر أساس المحرر.

**واجهة مغلقة عمدا:** لا يتعامل أي مكوّن مع `localStorage` مباشرة. عند الانتقال إلى Prisma تُستبدل أربع دوال فقط:

```
loadDocument / saveDocument / listDocuments / deleteDocument
```

دون تعديل أي مكوّن في المحرر.

**صيغة المفتاح:** `tashjeer:doc:v2:{ayahKey}`
**إصدار المخطط:** `schemaVersion` داخل كل مستند يسمح بالترقية التدريجية عبر `migrateDocument`.

**التصدير والاستيراد:** ملف JSON بصيغة `tashjeer-export`، صالح للمشاركة للمراجعة أو للنسخ الاحتياطي.

## 6. سير العمل في المحرر

```
1. اختر السورة والآية من شريط التنقل (أو ابحث في المصحف كله)
2. فعّل أداة التعليم (M)
3. انقر على الكلمة أو الكلمات التي فيها الاختلاف
4. اختر الفئة (أصول / فرش / مدود ...) ثم "إنشاء الاختلاف"
5. في نافذة التحرير:
   - اضبط العنوان والشرح والمرجع
   - أضف وجها: نصه، وصفه، ومن يقرأ به
   - سجّل الأدلة من النشر أو الطيبة
6. المحرك يرسم الخطوط تلقائيا فور الحفظ
7. راجع النتيجة، ثم Ctrl+S للحفظ
8. ارفع حالة المستند إلى "قيد المراجعة"
```

### التدقيق براو واحد

من لوحة الخصائص، اختر راويا واحدا في "تصفية الرواة". تظهر خطوطه وحدها، فيتحقق المدقق من قراءة هذا الراوي كاملة في الآية دفعة واحدة. هذه أقوى أداة تدقيق في المحرر.

## 9. ما لم يُنجز بعد

هذه قائمة صريحة بما يحتاج عملا بشريا أو مرحلة لاحقة:

- [ ] **إدخال الاختلافات الحقيقية**: البذرة الحالية 8 اختلافات بحالة مسودة للاختبار فقط.
- [ ] **تحرير الطرق**: التمييز بين طريقي الأزرق والأصبهاني عن ورش وأمثاله.
- [ ] **أرقام صفحات مصحف المدينة**: الحالية تقريبية محسوبة من توزيع الآيات.
- [ ] **الانتقال إلى قاعدة البيانات**: المخطط جاهز، والواجهة مغلقة ومستعدة.
- [ ] **المصادقة والصلاحيات**: صفحة الدخول حاليا محلية بلا تحقق.
- [ ] **اختبارات E2E**: متعذّرة في بيئة التطوير الحالية (تعذّر تنزيل المتصفح).
